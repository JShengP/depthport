## 範圍與核對方法

只讀先前凍結的 MOT20-01、MOT17-11／13 原偵測／預測／GT／完整 trace；不重跑偵測器或追蹤器，不作門檻搜尋、ReID、CMC、buffer 或確認修改。一般活躍弱延續、無競爭弱接回及原弱偵測完全保留。這是已知失敗後的事後診斷，不是新獨立驗收或預註冊實驗。

原政策、runner、probe、輸入、官方評估檔與已發布結果雜湊全部核對；每場景官方 CLEAR／Identity／HOTA 精確重現。獨立評估程序只觀察固定 [TrackEval HOTA](https://github.com/JonathonLuiten/TrackEval/blob/12c8791b303e0a0b50f753af204249e622d0281a/trackeval/metrics/hota.py) 原指派函式的參數／回傳，結束或失敗時還原；全部 HOTA 欄位與未加觀察時逐值完全一致。沒有另寫或替換指標演算法。

整段分析重複兩次，彙總 JSON 與本機全部 solver／歷史 JSON 雜湊相同；這不增加獨立樣本數。公開只有固定分類計數、成本分布及 IoU 門檻級數值，原矩陣、觀測橋接、逐格 ID、GT／事件位置留本機。資料授權／來源沿用[前輪紀錄](tracking-recovery-moving.md)：MOTChallenge／MOT16、MOT20，適用 CC BY-NC-SA 3.0，限本機非商業研究；不散布原片／GT，程式 AGPL 不改授權資料集。

## 如何對齊歷史，避免跨流硬比 ID

同一原始偵測以「影格、不可變快取索引」為鍵。先用最後共同觀測找另一流的假說，再要求介入前**完整且非空的觀測鍵歷史相等**，才接受橋接。兩流的原生 ID 數字完全不作相等依據；歷史已分歧者不強行對齊。這能識別相同輸入歷史的假說，不能保證假說對應真實同一個人。

GT 僅在追蹤完成後核對官方匹配。指標的 GT 歸屬、幾何支持及時間接近都不當成物理身分或因果標籤；保留參考組可能已錯接的情況。

## 前輪 22 筆新增漏追：三條不同路徑

原分類 **2 直接延後／12 弱階段未輸出／8 偵測仍輸出** 保持不變，現在補上歷史：

- **12 筆未輸出：** 全都能對到同一條在介入前觀測歷史相等的假說；在每筆漏配時，候選假說仍確認且仍在弱階段，預測年齡 **6–18 格**，沒有到期。該假說對原對照偵測的 IoU **全部低於既有 .10 門檻**，不能歸因於保留時間太短。
- 其中 **8 筆**沒有任何過門檻候選列；另 **4 筆**雖有其他過門檻列，但那些列都配到別的偵測，沒有可直接補上的空閒合格列。不能把幾何支持當作可用的一對一關聯，或直接建議剩餘邊重配。
- 參考組沿該假說提供這些觀測時，曾先後對上 **4 個不同 GT**；候選缺少更新後的幾何歷史與參考分歧。因此覆蓋損失伴隨參考假說跨 GT 接力的現象，不能把全部 FN 當成同一真實物件的可靠恢復被破壞，也沒有證據支持全面放寬 IoU／延長 buffer。
- **8 筆仍輸出：** 全部通過官方前處理，全部被 CLEAR 配給另一個 GT，且該 GT 都有同追蹤 ID 的連續性優先。若只作獨立單格 IoU .5 配對、拿掉時間連續性，**5／8** 的原 GT 會匹配。這個診斷不替換官方分數，說明的是關聯歷史與競爭如何影響評分，不是當格少了一個原始偵測。

剩餘 **2 筆**確為當格直接延後，不能用後續歷史解釋而忽略它們。這些計數屬相關影格觀測，不是 22 個獨立人物或事件。

## 新增換 ID：一筆位置變化，不等於多發一次實體換人

前輪的 **1 筆新增 IDSW 位置**，可和參考組同 GT 前一格的轉換配對。轉換前、後兩個假說在介入前各有完全相等的觀測歷史；候選先漏一格，再發生相同歷史對應的轉換，**時點延後 1 格**。

因此依「影格、GT」配對會出現一筆新增及一筆移除位置；本例支持**既有轉換的時點移位**，不是多發一次新的物理身分錯誤。原官方總數與配對計數都不改寫，亦不把這個結論外推到其餘事件。

## 公車 HOTA：定位門檻的取捨已找到具體來源

公車 HOTA 仍為 **24.9588→24.9473%**，不回填成通過。觀察官方原 solver 後，19 個門檻的 TP 與原 HOTA 全部一致：

- 所有流失匹配只出現在 **α=.05–.35**；去掉跨門檻重複後為 **5 個 GT×影格**。原匹配框對 GT 的 IoU 範圍約 **.3038–.3857**，在 CLEAR .5 下原本就不算 TP，卻能在較低 HOTA 門檻提供匹配。
- 這 5 個原觀測在候選輸出中都被移除：**2 個**在延後當格，**3 個**沿介入前歷史橋接的同一假說於後續發生。是確認 ID 輸出層的觀測損失，不是刪掉原弱偵測輸入；原快取完全相同。後續 3 個觀測中，假說都仍存在：2 個雖過 .10 門檻卻配到別的偵測，1 個低於門檻；不是全部由到期或再次直接攔截造成。
- 各低門檻仍可能有別的幾何支持，但官方加權一對一配對沒有將它們補給該 GT。HOTA 使用整段關聯權重再依定位門檻過濾；單格有框不保證可補匹配，也不能只用 CLEAR 的固定 .5 觀察解釋。
- α=.05–.35 對整體平均的貢獻約 **−.01697 個百分點**；α=.40–.95 約 **+.00552**，合計約 **−.01145**。高門檻的改善不足抵銷低門檻損失。

因此「CLEAR FP 減少」和「低定位門檻的行人觀測保留」在這裡有取捨；不能把所有被移除的 CLEAR FP 當成不存在的真人，也不能只保留合併分數宣稱無退步。MOT17-11 沒有流失匹配，僅在 .60／.65 各新增一個匹配；三場景分開記錄，不互相抵銷驗收失敗。

## 下一個控制點：有效、排他的競爭證據

三場景共 **10 次延後**（參考 CLEAR **2 TP／8 FP**），每次被列為競爭者的活躍假說都**已配到另一個偵測**。原規則只看同欄分數差，把這些已占用假說仍當作阻擋證據；這不等於有一個空閒且會搶同框的競爭者。

另外只在原矩陣上量測「強制競爭者改接該欄，再求其餘一對一指派」的總相似度機會成本，不回饋追蹤。保留上游先指派、後過門檻的規則；成本不是校準機率、真實 ID 損失或可直接跨矩陣比較的通用門檻。靜態 TP 兩筆成本約 **.0292–.5298**，FP 各場景範圍合計約 **.0070–.6697**，明顯重疊，沒有依據直接擬合新數值切點。

**決定：下一個獨立控制應先處理競爭者占用／指派替代的有效性，而不是再調啟用值、buffer 或丟棄弱偵測。** 但單純要求競爭者未配對，會排除這 10 個已觀察的阻擋決策；改規則後後續歷史也會變，可能產生別的曝光，不能由此推算整段必然零觸發、等同對照或保有原 FP 收益。下一輪需先凍結有效競爭定義與風險標準，再選有實際曝光的授權序列；本輪不實作或調整新閘門。幾何狀態延續、GT 競爭及低定位框的觀測保留另立控制，不把多種改動混在一起。

## 重現與限制

使用固定 NumPy 2 研究環境與乾淨 TrackEval，供應先前本機資料；無網路操作、無原始診斷上傳：

```bash
python tools/diagnose_tracking_recovery_history.py \
  --study local/static-manifest.json docs/validation/v0.3-recovery-deferral.json artifacts/static/run \
  --study local/moving-manifest.json docs/validation/v0.3-recovery-moving.json artifacts/moving/run \
  --trackeval-root local/TrackEval --work-dir artifacts/history/run \
  --output artifacts/history/aggregate.json
```

工具驗證原凍結程式／輸入／預測／trace 與官方評估檔，拒絕分數不符；完整 solver 成本、橋接及案例只寫在本機。這是演算法／評分機制診斷，不能證明物理遮擋或真實身分因果；既有場景不是新盲測。長遮擋、實體 RTSP、Windows 真推論／worker、3D、長時穩定性及吞吐量仍未驗收，既有 Release／Tag 與預設不變。
