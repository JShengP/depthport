## 來源與條款

官方 [MOT17 封存資料](https://motchallenge.net/data/MOT17/) 採 [CC BY-NC-SA 3.0](https://creativecommons.org/licenses/by-nc-sa/3.0/)，原始來源條件也可能適用；保留 MOTChallenge 貢獻者及 MOT17／MOT16 標註來源。使用 MOT17-09-DPM（525 格、低角度行人街景，抽查為固定視角）與 MOT17-10-DPM（654 格、夜間移動相機），皆為 30 fps，僅在本機非商用研究。未重用上一輪 04／11／13，也不把同場景不同偵測器後綴當成獨立序列。

共 1,179 格官方壓縮預覽影像，解析度 960×540；GT 為 1920×1080。核對官方壓縮檔、GT、序列資訊、影片及快取雜湊；預測框先放大 2 倍，再將 x／y 加 1 還原 MOT 座標。公開內容僅含彙總、設定、來源識別、雜湊與統計圖；影片、GT、事件時間窗／ID、逐格預測、權重、抽查影像及本機路徑都留在本機。程式 AGPL 授權不會取代資料集條款。

## 固定比較方式

候選參數在本組第一次追蹤執行前寫入本機具時間戳的比較計畫，並非獨立研究註冊。每序列只有一份真正 CPU YOLO26n 偵測快取，所有候選共用：Ultralytics 8.4.115、imgsz 640、confidence .10、NMS .70、人類別 0、上限 64。偵測器與模型沿用上一輪。Roboflow Trackers 2.6.1 在獨立 NumPy 2.2.6 環境執行，主程式保持 NumPy 1.26.4；未加入 ReID、未做 CMC 消融、不含 worker IPC，也未變更應用程式預設值。

ByteTrack／BoT-SORT 各測 5 組，數字依序為**啟用門檻／高信心分流門檻／保留時間參數**：

- **原始預設：** .70／.60／30。
- **只降啟用：** .30／.60／30。
- **同步降門檻：** .30／.30／30。
- **只延長保留：** .70／.60／90。
- **同步降門檻＋延長保留：** .30／.30／90。

保留參數以 **30 fps 參考影格**為單位，30 是 1 秒、90 是 3 秒，由函式庫依來源 FPS 換算。其他參數固定，包括兩格確認、關聯門檻及 BoT-SORT 的 CMC。新追蹤必須同時通過高信心分流及啟用門檻，因此只把啟用降至 .30，仍無法讓 .30–.60 偵測建立新 ID。降低分流門檻也會改變偵測進入的關聯階段及 BoT-SORT CMC 的前景遮罩，不能把效果全部歸因於啟用門檻。

工具核對後端實際門檻與時間預算；每個後端／候選／序列獨立重跑 3 次並輪換順序，固定 OpenCV RNG seed 0／單執行緒，完成 **60 次完整執行**。更新延遲包含第一次更新，不含偵測、解碼及啟動，取各次 P50／P95 的中位數，只描述本機條件，不代表端到端即時驗收。初次執行在影像抽查後修正 09「移動」分類為「固定」，該次未採用；正式紀錄全數以正確分類及原候選參數重新執行。

整段 CLEAR（IoU .5）、Identity、HOTA 使用固定且未修改的 [TrackEval](https://github.com/JonathonLuiten/TrackEval/tree/12c8791b303e0a0b50f753af204249e622d0281a)，含官方 MOT17 行人／干擾物前處理，彙總使用原評估器合併函式。舊版 NumPy 別名只在記憶體提供。

## 結果

官方整段彙總共 18,164 次行人 GT 出現；每行依序列出 **Recall／Precision／IDF1／HOTA**（百分比），接著為**換 ID 次數／誤追次數（FP）**。各場景、斷裂、延遲及正規化預測雜湊另見 JSON，全部重跑的正規化預測一致。

**ByteTrack**
- **原始預設:** 40.15 / 89.80 / 35.87 / 29.85; **140 / 828**.
- **只降啟用:** 43.21 / 87.53 / 37.38 / 30.82; **170 / 1,118**.
- **同步降門檻:** 50.02 / 77.40 / 33.91 / 29.29; **432 / 2,652**.
- **只延長保留:** 40.25 / 89.63 / 36.04 / 29.77; **139 / 846**.
- **同步降門檻＋延長保留:** 50.14 / 76.99 / 33.67 / 29.25; **449 / 2,722**.

**BoT-SORT**
- **原始預設:** 37.34 / 94.67 / 41.51 / 33.71; **49 / 382**.
- **只降啟用:** 39.21 / 94.18 / 42.96 / 34.52; **58 / 440**.
- **同步降門檻:** 46.21 / 84.59 / 38.88 / 33.39; **205 / 1,529**.
- **只延長保留:** 37.34 / 94.67 / 41.43 / 33.66; **49 / 382**.
- **同步降門檻＋延長保留:** 46.29 / 84.55 / 39.05 / 33.40; **201 / 1,537**.

**只降低啟用是本組較溫和的覆蓋改善候選：** ByteTrack Recall 40.15→43.21%、BoT-SORT 37.34→39.21%，IDF1／HOTA 也提高，但新追蹤仍須通過原 .60 分流。代價為換 ID 140→170、49→58，FP 828→1,118、382→440，不能宣稱全面改善。

**同步降兩個門檻更激進：** Recall 達 50.02%／46.21%，但 Precision 降至 77.41%／84.59%、換 ID 增至 432／205，IDF1／HOTA 皆低於各自預設。在此基礎延長保留，覆蓋增益很小，也未恢復長事件 ID。因此不把 .30／.30 組升為預設，應用程式及 worker 原設定維持不變。


## 遮擋與交會證據及限制

沿用上一輪只依 GT 選事件的規則：visibility ≤.30 持續至少 1 秒，前後 1 秒內須有 ≥.60 的可見錨點；交會候選要求投影框 IoU ≥.10 並出現水平順序互換。得到 **21 個長低可見度事件／21 個對象**及 **23 個重疊／順序互換事件／46 次對象出現**。自訂端點診斷使用官方前處理後、全畫面一對一 IoU≥.5 配對，不是官方分情境 MOT 指標；漏配端點仍納入全部對象分母。

每個候選都與同後端預設在完全相同的事件／對象上逐一配對，記錄從換 ID／漏配變成同 ID 的改善、反向退步及端點覆蓋增減。只在各次執行內判斷 ID 是否延續，不直接比較不同執行的 ID 數字。

每場景抽查最長低可見度事件及 GT-ID 排序第一個交會候選，共 **44 個候選中的 4 個、12 張前／中／後影格**，符合可見度降低及投影順序互換；並非完整的人工作業或實體遮擋／3D 交會真值，影像不公開。另外用真正函式庫做合成機制測試，確認 .40 偵測被 .60 分流門檻阻擋、同步降低後可啟用，以及靜止追蹤可在 3 秒保留下跨過 45 格空檔；這只驗證參數作用，不代表真實影片表現。

依「預設／只降啟用／同步降門檻／只延長保留／兩者合併」順序，**21 個長事件中保持同 ID**的 ByteTrack 為 **0／0／0／1／0**，BoT-SORT 為 **1／1／0／1／0**。至少一個端點漏配分別為 **15／15／12／15／12** 與 **16／15／12／16／12**。

逐一配對確認，ByteTrack 只延長保留將**原本換 ID 的 1 個事件改善為同 ID**，未失去預設的同 ID 事件；該例位於移動相機序列 10。BoT-SORT 單獨延長保留沒有新增長事件 ID 延續。兩個同步降門檻的 BoT-SORT 組則**失去原本在固定視角序列 09 保留成功的 1 個事件**。降低雙門檻多找回 ByteTrack 3／BoT-SORT 4 個對象的端點配對，但新增配對並未轉為同 ID 恢復。

46 次交會候選對象中，同 ID 數為 ByteTrack **16／17／17／16／17**、BoT-SORT **23／25／26／23／24**；端點漏配為 **15／12／10／14／9** 與 **18／15／11／18／11**。覆蓋改善仍須連同整段 FP／換 ID 代價判讀。

另外抽查 ByteTrack 改善與 BoT-SORT 退步各 1 例，比較預設及候選的前／中／後，共 2 個針對性案例、12 個影像面板，支持該 GT 對象的可見度降低及端點狀態變化，不能證明事件中途 ID 全程正確；影像及配對 ID 留在本機。**21 個對象僅改善 1 例，不能算通過一般長遮擋驗收。**只降啟用可保留為研究候選；下一步應檢查換 ID／誤追原因及移動時的關聯，再決定預設或 ReID，未依本次結果繼續搜尋其他參數。


本組雖為專案尚未比較的序列，仍是 MOT17 訓練預覽，不能視為無偏的最終選型／測試切分。長低可見度未必代表完全沒有偵測；前後同 ID 也不保證中途持續正確追蹤或沒有污染。實體 RTSP、校正 3D、Windows 真模型／worker、長時間穩定性及端到端效能仍須另外驗收。

## 本機重現

沿用[上一輪重現方式](tracking-expanded-acceptance.md#本機重跑)相同旗標建立兩份快取，來源網址與雜湊見彙總 JSON。獨立環境安裝 `requirements-tracking-worker.txt`、紀錄中的 SciPy，及固定未修改的 TrackEval；本機 manifest 格式同前，09 標為固定、10 為移動。參數比較模式會拒絕上一輪 04／11／13。

```bash
.venv-trackers/bin/python tools/validate_mot_tracking.py \
  --manifest local/mot17-new-group.json --trackeval-root local/TrackEval \
  --work-dir outputs/mot17-parameters --output outputs/mot17-parameters.json \
  --repeats 3 --parameter-sweep

# 同一獨立環境另裝 pytest>=8,<10，可選擇執行真函式庫機制測試：
RUN_TRACKERS_CONTRACTS=1 .venv-trackers/bin/python -m pytest -q tests/test_tracking_parameters.py
```

`run_video_tracker(..., parameters={...})` 僅接受有界的直接函式庫啟用／分流／保留參數；未知欄位、無效數值或對 worker／Baseline 覆寫都明確拒絕。原呼叫保持原行為。工具不下載、不上傳，公開前須檢查彙總；CI 執行合成契約，真函式庫機制測試另行啟用，不下載資料集、追蹤套件或權重。
