## 輸入與官方數字核對

重用上一輪 MOT17-09／10 共 1,179 格的固定偵測快取及保存結果，僅比較**預設與只降啟用門檻**：啟用 .70→.30、高信心分流仍 .60、保留 1 秒、其他條件不變。未重跑模型／追蹤器，也未依結果搜尋新參數。重建 8 份保存執行（兩組參數×兩後端×兩序列），核對正規化預測、快取、影片、官方 GT／壓縮檔雜湊，沿用預覽放大與 MOT x／y 加 1 座標。

新離線工具重建固定版 [TrackEval CLEAR](https://github.com/JonathonLuiten/TrackEval/blob/12c8791b303e0a0b50f753af204249e622d0281a/trackeval/metrics/clear.py) 的決策：先優先延續上一個步驟的 ID，再比較 IoU；IoU≥.5，換 ID 與該 GT 歷史最近一次配對比較，保留空影格的原評估器行為。每份結果的 **TP／FP／FN／IDSW** 必須同時等於未修改的官方評估器及已公開參數紀錄，8 份全數核對通過。這與先前端點診斷的獨立逐格 Hungarian 配對不同。

換 ID 以 **影格＋GT** 配對位置，共有位置仍可能是不同轉換，絕不跨執行直接比 ID 數字。FP 在官方干擾物前處理後，以唯一框位置／信心映射至**影格＋固定快取偵測索引**，有歧義就拒絕。以下是觀測次數，不是不同人物或獨立事故數。

## 偵測、可見度與關聯的證據

新增換 ID 的互斥**情境特徵**為：

- 配對缺口中，至少一個 GT 存在的影格沒有 IoU≥.5 原始框：**45／68、26／28**。
- 缺口中各個 GT 存在影格均有原始幾何框支持：**8／1**。
- 連續配對中發生投影框重疊／交會附近換 ID：**6／0**。
- 其他連續換 ID：**9／1**，仍未能分離框位置、關聯及評分敏感度。

這些不是互斥的根因。原始框可能低於高信心門檻、對應擁擠場景另一人或位置不穩；支持只檢查單一 GT 幾何，不是一對一偵測評分。GT 缺席另行記錄。「沒有足夠 IoU 的框」可能是只框到上半身，並非完全沒有偵測。

可重疊訊號也顯示成因混合：低可見度情境 **35／21**、長低可見度事件附近 **9／5**、順序互換事件附近 **11／4**；當前 GT 與其他 GT 框重疊 **49／19**，候選 ID 最近曾配給另一個 GT **25／4**。缺口曾有部分框重疊（.10≤IoU<.50）**42／26**、幾乎沒有重疊（IoU<.10）**17／10**；足夠可見但缺少有效框 **17／11**，低可見且缺框 **30／20**。這些訊號互相重疊，不能相加當根因比例。

新增 FP 分為：**140／19** 個重複框或配對競爭、**133／39** 個部分重疊（.10≤IoU<.50）、**24／0** 個與可評分行人幾乎無重疊。「競爭」指未配對輸出仍以 IoU≥.5 重疊某 GT，不能直接證明兩個框是同一個實體人。沒有新增 FP 與被排除標註 IoU≥.5，也不能因此假設所有人都有完整標註。

新增 FP **249／297、36／58** 的當前信心低於 .60。這是既有軌跡輸出信心，不是建立 ID 時的信心：降低啟用讓軌跡從 ≥.60 偵測建立後，仍可能沿用較弱偵測。它們分成 **102／19** 個連續軌跡／類別片段，中位 **2／2 格**、最長 **16／12 格**；序列、軌跡、分類或影格中斷都切段，不等於不同物件數。**38／17** 個新增 FP 所屬軌跡整段從未有官方 TP，**164／4** 個所屬軌跡曾配到多個 GT；單一訊號均不能證明實體根因。

## 影像案例檢查

依固定規則，每個可用後端／錯誤／分類選 1 例：FP 取最長連續片段，換 ID 取最長配對空檔，再用固定排序解同分。完整檢查 **12 例（7 換 ID、5 FP）、72 個預設／候選面板、33 張不同來源影格**。這是診斷取樣，不是隨機、完整驗收或根因盛行率估計。

抽查支持以下情況：

- 發光廣告看板上的人物被 ByteTrack 啟用為額外軌跡，是具體背景誤啟用案例。
- 花台後的真人只偵測到上半身，而 GT 是全身框；兩後端皆有同一場景條件。此處的 FP 屬框位置／可見部份不一致，不能解讀成虛構人物，兩後端影像也不是兩個獨立場景證據。
- 附近行人框出現多輸出競爭；擁擠、部分遮擋對象在有原始框的短缺口後換 ID，支持關聯與弱框歧義的可能性，但不是已確認的 3D 交會。
- 長缺口混合弱框／位置不準、可見度降低及 ID 所有權改變；小型持續可見對象也有相鄰影格換 ID，其中預設本來漏追。現有框資訊無法把所有案例壓成單一原因。

公開僅含語意觀察與彙總；原圖、裁切、影格位置、物件 ID、偵測索引、逐格追蹤及案例對應檔均留在本機。

## 改善決定

1. **下一個控制實驗先分離「新 ID 啟用」與「既有 ID 延續」。** 原兩格確認與 3／5 格或信心歷史確認比較；接近相容的活躍／遺失軌跡時，先暫緩新 ID 確認，同時保留弱偵測供舊軌跡恢復。一起量 TP 收益、FP／換 ID 代價，不直接濾除所有低分框，以免丟掉找回的 TP。廣告能持續多格，延長確認本身不保證解決所有誤啟用。
2. **分離偵測框品質。** 固定追蹤器，在其他序列比較解析度／偵測設定，特別檢查遮擋的半身／全身框差異與小物件。官方 IoU 評分保持不變，調低評估門檻不算修好。
3. **先記錄關聯／恢復成本，再調參。** 在本機記錄成本、運動／IoU 門控及多個活躍／遺失候選，優先檢查有偵測仍中斷的短缺口，以及最近屬於其他 GT 的 ID。短於目前保留預算的缺口不能只歸因於保留時間；ReID 留待後續，不預設能修好框位置或重複啟用。
4. **分開評估不同群體。** 保留新增／消失／共有數字、預設有配對／未配對群體及全部事件漏配分母；每項修正分開在另一組資料驗證，再決定是否改預設。

以上為已排序的後續實驗決定，尚未實作追蹤行為修正或宣稱效果；本次程式更新是可重現診斷及證據。

## 重現與條款

使用上一輪本機 manifest、保存的預測／MOT 檔、公開參數彙總，以及獨立 NumPy 2 環境內的固定未修改 TrackEval：

```bash
.venv-trackers/bin/python tools/diagnose_tracking_errors.py \
  --manifest local/mot17-new-group.json \
  --validation-record docs/validation/v0.3-mot17-parameters.json \
  --runs-dir outputs/mot17-parameters --trackeval-root local/TrackEval \
  --work-dir outputs/tracking-diagnosis --output outputs/tracking-diagnosis-summary.json
```

工具不下載、不跑模型、不上傳。原始案例清單／ID 對照及選樣檔寫入本機工作目錄，只有彙總輸出才是可公開候選。公開 JSON 的影像觀察由輔助檢視後加入，並非自動分類就能得知語意；CI 只執行合成契約，不使用影像或權重。
